# ログアウト Implementation Plan

> **For agentic workers:** `executing-plans` スキルを使い、各TaskをRed → Green → Refactorで実行する。Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ログイン中の利用者が通常のログアウト操作で現在のブラウザの認証を終了し、ログイン画面で3秒通知を確認できる。

**Architecture:** applicationが操作時のactor照合とセッション終了の契約、appのAuth.jsアダプターがCookie操作、Actionが表示キャッシュ・通知・固定先へのredirect、UIがナビと送信状態を担当する。DBの利用者・投稿・関係を変更しない。

**Tech Stack:** 導入済みAuth.js `5.0.0-beta.32`、Next.js、React、Vitest、Playwright。migration・新規依存なし。

**Status:** 実装前。[全体計画](2026-10-26-remaining-core-features.md)の第6段階。フォローまで完成・レビューしてから着手する。

## 仕様

- 通常のログアウト画面は作らない。ログイン中の共通ナビへ「ログアウト」ボタンを追加する。PC・375px双方で操作できる。
- 既存の自分のプロフィールのアカウント操作領域にも同じボタンを置き、アカウント削除と近い位置にする。同じActionを使い、二重実装しない。
- 押すと現在のブラウザのセッションを終了し `/login` へ移動、「ログアウトしました」を3秒表示する。再読込で再表示しない。他ブラウザのJWTを一括失効する機能は含めない。
- Auth.jsの `signOut({redirect:false,redirectTo:'/login'})` を使う。Cookie名を固定して手動削除しない。DBの利用者が消えていても、DB障害中でも、認証Cookieを終了できる設計にする。
- セッション取得にauthを使い、ユーザーDBの実在確認をログアウト実行の前提にしない。認証処理そのものが失敗した場合は失敗表示とする。
- 画面表示時のAと送信時のBが違う場合はBをログアウトさせない。既に匿名・期限切れならCookieを清掃して/loginへ移動できる。ログアウトの成否と利用者の削除を混同しない。
- pending中は二重送信を防ぐ。失敗時は成功通知・成功redirectを出さず、現在の画面で「ログアウトできませんでした。もう一度お試しください」を表示する。
- GETによるログアウトは作らない。画面案の「もっと見る」メニュー全体を新たに作る必要はなく、まず明示的なボタンを置く。
- logout後のhomeは公開一覧として閲覧可能で、本人用の編集・削除・ログアウト導線が消える。followingOnly・favorites・profile edit/deleteへの直接アクセスは既存の認証ガードで/login。
- 戻る・進むで本人用の表示やお気に入りの内容が復活しないこと、保持されたダイアログがlogin画面を覆わないことを確認する。
- logoutによって投稿・画像・favorites・follows・retweetsを消さない。未確定の下書きが残る場合は既存の期限切れ回収を維持する。

## ポートとAuth.js境界

```ts
// application/auth/ports/session-terminator.ts
export interface SessionTerminator { end(): Promise<boolean> }
// application/auth/logout.ts
export type LogoutResult = {ok:true} | {ok:false;code:'SESSION_CHANGED'|'UNAVAILABLE'};
export async function logout(
  deps:{sessions:SessionTerminator},
  input:{actorId:string|null;expectedActorId:string},
):Promise<LogoutResult> {
  if(input.actorId !== null && input.actorId !== input.expectedActorId)
    return {ok:false,code:'SESSION_CHANGED'};
  try { return await deps.sessions.end() ? {ok:true} : {ok:false,code:'UNAVAILABLE'}; }
  catch { return {ok:false,code:'UNAVAILABLE'}; }
}
```

`app/_auth/end-session.ts` がSessionTerminatorを実装する関数を公開する。既存の `app/_auth/auth.ts` と `isSuccessfulSignOut` を使い、アダプターを `app/_composition/session.ts` で組み立てる。applicationからNext/Auth.jsをimportしない。infraからappの認証設定を逆importするクラスは作らない。

導入版 `node_modules/next-auth/lib/actions.js` ではredirect:falseのsignOutがAuthのレスポンスを返し、Cookie操作はAuth.js自身が行う。戻り値のredirectがエラーURLでないことを既存ヘルパーで確認する。「例外がない」だけで成功としない。ライブラリの挙動が異なった場合は型・実装を確認し、テストで契約を固定する。
