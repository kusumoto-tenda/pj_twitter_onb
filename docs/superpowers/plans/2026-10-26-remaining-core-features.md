## 共通契約

- 資料は `docs/functions.md`、`docs/front_design.md`、`docs/front/`。ER図にはLikeとFavoriteが別々にある。利用者の確認により、Likeは「♡」で相手からも見える反応、Favoriteはカード右端の旗のようなアイコンで自分専用の保存。相互に流用しない。
- LikeとFavoriteをそれぞれ独立した必須機能としてこの6計画に含める。Likeは公開件数と公開プロフィールの「いいね」タブを提供し、Favoriteの保存関係は公開しない。
- お気に入りはbookmarkとして扱う。本人だけが `/favorites` を閲覧でき、他人のお気に入り一覧・公開件数は提供しない。本人専用であることは利用者確認済み。プロフィールに新しい公開お気に入りタブは追加しない。
- リツイート・フォローの既存データ表示は維持する。任意機能の報告、動画、鍵アカウント、リンク自動変換、パスワード強度チェックはこの6計画に含めない。
- 全変更系Actionは毎回セッションを確認する。画面表示時のactor UUIDと現在のactor UUIDが違う場合は `SESSION_CHANGED` とし、どちらの利用者のデータも変更しない。比較値は認証の代わりではなく、操作対象の利用者を取り違えないための追加確認。
- 所有者・実行者・時刻はサーバーで決める。hidden値・previousState・URLのユーザーIDをactorとして採用しない。対象は内部UUIDで固定する。
- お気に入り／いいね／リツイート／フォローは `active: true | false` を厳密に受け取る。`Boolean('false')` は使わず、FormDataなら `'true'`／`'false'` 以外を拒否する。DBの現在値を反転するtoggle APIは作らない。
- 同じ状態への再送は成功とする。登録済みへの登録でID・created_atを作り直さず、解除済みへの解除は何もしない。別タブから登録／解除が重なった場合はDBで成立した最終状態を採用し、操作履歴の全順序保証は追加しない。
- 初期表示の状態と、同じ元投稿が複数カードにある場合の状態はDBを正とする。最初は成功後に再取得する方式を採用し、楽観更新による巻き戻し処理を増やさない。
- 匿名のお気に入り／いいね／リツイート／フォロー操作は「ログイン中のみ…できます」の3秒通知だけ。画面遷移・書込みなし。本人専用のお気に入り一覧URLへ直接アクセスした場合は `/login`。公開のいいねタブは匿名でも閲覧できる。
- Mutation後に `/`、`/profile/[displayId]`、段階2以降は `/favorites` を無効化する。フォロー操作はログイン中の利用者の他人プロフィール表示にも影響するので、対象者だけに無効化を絞らない。
- 通常の操作はURL・タブ・カーソルを維持する。解除や削除でページが空になっても勝手にホーム先頭へ移動せず、空表示と「最新に戻る」を用意する。
- 同じ操作の連打をpending中無効化し、障害時は既存の表示を維持して再試行できる。GETによる登録・解除・削除・ログアウトは実装しない。
- SQLの取得はページ選択後に集約し、件数増加でクエリ回数が増えないようにする。ページングは20+1件、UTC6桁精度とUUIDによるキーセットで、Dateに変換しない。

## 各TaskのTDDサイクル

1. 個別計画のテストケースを書く。
2. 記載コマンドで実行し、意図した未実装・不正挙動でFAILすることを確認する。
3. ポートと契約に必要な最小実装を追加する。
4. 同じテストをPASSにし、必要な重複のみ整理、型チェック。
5. 1Taskを1コミットの目安にする。コンパイルエラーのままコミットしない。E2E先行Taskの期待するFAILだけは計画上の未実装として記録する。

各機能のTask6では `pnpm test:unit`、`pnpm typecheck`、`pnpm test:integration`、`pnpm test:e2e`、`pnpm build` を実行する。新規E2Eは連続2回通す。DB・Blobは専用テスト環境と既存の分離チェック経由だけを使い、資格情報未設定や接続失敗を成功扱いのskipにしない。

導入版の `node_modules/next/dist/docs/01-app/02-guides/server-actions.md`、`03-api-reference/04-functions/revalidatePath.md`、`03-api-reference/05-config/01-next-config-js/reactStrictMode.md` を読む。Auth.jsはローカルの型・実装でsignOutの戻り値とCookie操作を確認する。
