# いいね Implementation Plan

> **For agentic workers:** `executing-plans` スキルを使い、各TaskをRed → Green → Refactorで実行する。Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ♡からいいねを登録・解除でき、公開件数とプロフィールの公開「いいね」タブを通じて相手からも反応を確認できる。

**Architecture:** domain/applicationがUUID・明示的な登録解除・公開一覧取得の契約、infraがLike専用テーブルの一意制約・CASCADE・ページ取得、appがセッション確認・ハート・公開タブ・通知・再取得を担当する。Favoriteの自分専用保存とは独立したデータ・操作にする。

**Tech Stack:** 現行Next.js、React、Auth.js、TypeScript、postgres、Vitest、Playwright。migration006のみ追加し、新規サービス・ライブラリは追加しない。

**Status:** 実装前。[全体計画](2026-10-26-remaining-core-features.md)の第3段階。第2段階のお気に入りと、その後の[投稿ダイアログの通信失敗対応](2026-10-26-dialog-action-network-errors.md)を完成・レビューしてから着手する。今回の作業は文書のみ。

## 1. 仕様と公開範囲

- 利用者確認済みの区別：**いいね＝♡＝相手からも見える反応、お気に入り＝右端の旗＝自分専用の保存**。既存Favoriteのデータ・ボタン・保存一覧をいいねとして流用しない。
- メイン、フォローのみ、プロフィールの各投稿一覧、お気に入り一覧の元投稿カードにハートを表示する。未登録は輪郭、登録済みは塗りつぶし。アクセシブル名は「いいねする／いいねを取り消す」、aria-pressedで状態を示す。
- いいね件数は公開。閲覧者本人の登録状態も表示する。リツイートカードでも対象は元投稿UUIDであり、リツイート行や実行者へのいいねにしない。自分の投稿へのいいねも許可する。
- プロフィールに公開の「いいね」タブ `?tab=likes` を追加する。本人・他人・未ログインの誰でも、その利用者がいいねした投稿を閲覧できる。投稿者も相手のプロフィールから反応を確認できる。これは「相手からも見える」を具体化した補完仕様。
- 公開一覧はいいね日時の新しい順 `(like.created_at, like.id)`、20+1件。投稿自体の作成日時は変えない。いいねをホームタイムラインの新しい出来事として追加しない。
- 未ログインのクリックは「ログイン中のみいいねできます」を3秒表示し、その場に留まる。操作は書き込まず、ログイン画面へ移動しない。公開のいいねタブ閲覧には認証を要求しない。
- 登録済みへの登録はID・created_atを維持、解除済みへの解除は成功。解除後の再登録は新しいID・日時とし公開一覧の先頭側へ出す。
- 変更系Actionは現在のセッションと画面表示時のactorを比較する。Aで表示した後Bへ切り替えた場合、どちらのいいねも変更せずSESSION_CHANGED。投稿者ではなくログイン中の利用者だけが自分のいいねを解除できる。
- pending中は連打を防ぎ、失敗時は状態・件数を維持して3秒通知。成功後は現在URL・タブ・カーソルを維持してDB状態を再取得し、同じ元投稿の全カードを更新する。
- 投稿編集はいいねを維持し公開一覧にも現在の本文・画像を表示する。投稿削除・投稿者退会で関連いいねが消える。いいねした人の退会ではその人のいいねだけが消える。
- お気に入りの登録状態・保存一覧は引き続き本人専用。公開いいね一覧で、対象利用者が何をお気に入り保存したかを返さない。
- 投稿ごとの「いいねした人一覧」ダイアログ、通知欄、メール通知、いいねを非公開にする設定は今回含めない。件数を押すと未実装画面へ移動するUIも作らない。

## 2. DB・ポート・読取モデル

ER図Likeの `executor_id / tweet_id / created_at` に合わせ、Favoriteとは別テーブルを作る。

```sql
-- infra/db/migrations/006-create-likes.sql
CREATE TABLE twitter.likes (
  id UUID PRIMARY KEY,
  executor_id UUID NOT NULL REFERENCES twitter.users(id) ON DELETE CASCADE,
  tweet_id UUID NOT NULL REFERENCES twitter.tweets(id) ON DELETE CASCADE,
  created_at TIMESTAMPTZ NOT NULL,
  CONSTRAINT likes_executor_tweet_unique UNIQUE(executor_id, tweet_id)
);
CREATE INDEX likes_executor_created_idx ON twitter.likes(executor_id, created_at DESC, id DESC);
CREATE INDEX likes_tweet_idx ON twitter.likes(tweet_id);
```

```ts
// application/likes/ports/like-repository.ts
export interface LikeRepository {
  set(input:{actorId:string;tweetId:string;active:boolean;id:string;now:Date}):
    Promise<{status:'set';active:boolean;count:number}|{status:'actor-not-found'|'tweet-not-found'}>;
}
// application/likes/like.ts
export type SetLikeResult =
  | {ok:true;active:boolean;count:number}
  | {ok:false;code:'UNAUTHENTICATED'|'SESSION_CHANGED'|'INVALID_REQUEST'|'NOT_FOUND'|'UNAVAILABLE'};
// setLike input: {actorId:string|null;expectedActorId:string|null;tweetId:string;active:boolean}

// application/profile/profile.ts（TimelineItemは既存型をimport）
export type LikeCursor = {createdAt:string;likeId:string};
export type ProfileLikesPage = {
  items:{likeId:string;likedAt:string;item:TimelineItem}[];
  nextCursor:LikeCursor|null;
};
// ProfileQueryへ追加：
// findLikedPage(input:{subjectId:string;viewerId:string|null;after:LikeCursor|null;limit:number})
//   :Promise<ProfileLikesPage>;
// TimelineItem.tweetへ likedByViewer:boolean / likeCount:number を追加。
```

- SQLは `sql.begin` 内で対象投稿をFOR UPDATEし、actor実在を確認。登録は `INSERT ... ON CONFLICT (executor_id,tweet_id) DO NOTHING`、解除は `DELETE WHERE executor_id=actor AND tweet_id=target`。同じ元投稿への操作を直列化し、最後にactiveと件数を読み返す。
- actor消失は未認証、対象消失はNOT_FOUND。識別したFKエラーだけ分類し、無関係なSQL障害を成功扱いしない。投稿の本文・日時・revisionは更新しない。
- 一覧はsubjectIdがいいねした投稿を取得する。likedByViewer/favoritedByViewerは現在のviewerについて計算し、subjectと混同しない。匿名の本人状態はfalseでも件数と公開一覧は取得できる。
- ページ選択を先に行い、その後に画像・件数・本人状態を集約する。複数画像・いいね・favoritesのJOINで件数や行数を掛け算にせず、1ページ1SQLを維持する。
- カーソルはsubject UUID・likes・UTC6桁時刻・like UUIDに結び付ける。既存cursor-validationを使い、年0000・不正日時・他subject／他tab・重複値を拒否する。Dateへ丸めずSQL比較は文字列経由で行う。
- likesは `ProfileTab` に追加するが `TimelineEventKind` はtweet/retweetのまま。既存ActivityTabのカーソルにlikesを混ぜず、parseLikeCursor/encodeLikeCursorを追加する。
